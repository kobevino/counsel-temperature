# Counsel Chat Workspace with Conversation Temperature

## Overview

보험 상담사가 고객과 채팅 상담을 진행하면서, 우측 패널에서 AI가 분석한 "대화 온도(이탈 위험도)"를 실시간으로 확인하는 어드민 워크스페이스 프로토타입.

- API 서버 없이 동작하는 프로토타입: 고객 목록·대화 스크립트는 mock 데이터, 유일한 실제 백엔드 호출은 대화 온도 분석(Next.js Route Handler → Anthropic API)뿐이다.
- 화면 구성과 디자인은 Figma 시안(`상담 워크스페이스`, node `2:482`)을 따른다.
  https://www.figma.com/design/eHHeQUdLru0DAIlcecHMUy/Untitled?node-id=2-482
- 핵심 가치는 우측 "AI 상담 코치" 패널이다. 나머지 세 컬럼은 데모 맥락을 만들어 주는 조연이다.

## Tech Stack

- Next.js (App Router, TypeScript)
- Tailwind CSS (Figma 시안 재현)
- Zustand — 채팅 세션 상태(메시지, 대본 커서, 타이핑 상태, 온도 스냅샷 이력)
- TanStack React Query + axios — 온도 분석 API 호출(mutation), 로딩/에러/재시도 처리
- Zod — 온도 분석 응답 스키마 정의 및 검증
- Anthropic SDK (`@anthropic-ai/sdk`) — 서버 전용. Route Handler에서만 사용하고 클라이언트 번들에 포함하지 않는다.

| 컬럼 | 폭 | 내용 |
|---|---|---|

| 대화 | 560px | 대화 헤더(고객명, 상태, 담당 상담사), 메시지 목록, 입력창 + 빠른 작업 칩 |
| 고객 정보 | 280px | 기본 정보(고객 ID, 연령, 관심 상품, 유입 경로, 상담 시작), 상담 태그 |
| AI 상담 코치 | 300px | **대화 온도계 — 이 스펙의 핵심** |

## Feature 1 — 고객 목록 (mock)

- Figma의 4명 고객을 mock으로 재현: 박윤수(활성, "이탈 위험 71%" 표시), 김지은, 이도현, 최민아.
- 각 항목: 프로필 원형, 이름, 최근 메시지 1줄, 상대 시간(방금/3분 전 등), 위험 고객만 위험 라벨.
- 선택된 고객은 좌측 보더 + 배경 하이라이트. 고객 클릭 시 해당 상담 세션으로 전환.
- 상태 탭·검색은 시각적 재현만 하고 실제 필터링은 하지 않아도 된다(프로토타입 범위 밖).

## Feature 2 — 채팅 (대본 재생 방식)

실시간 통신 없음. 고객 응답은 mock 대본 큐에서 재생한다.

- **상담사는 자유 입력**, 고객 응답은 대본에서 순서대로 나온다.
- 상담사 전송 → 고객 타이핑 인디케이터 표시 → 응답 길이에 비례한 지연(약 0.6~2.5초) → 고객 발화 append.
- **분기 지점**: 온도가 크게 꺾이는 대본 스텝에서는 고객 응답 후보 2~3개를 데모 운영자가 선택할 수 있다(예: "관심" vs "보류").
- **대본 힌트(데모 모드)**: 입력창 위에 다음 대본이 기대하는 상담사 질문을 흐리게 표시.
- 메시지 타임스탬프는 실제 시각이 아닌 세션 시작 기준 오프셋 — 데모 재실행 시 항상 같은 타임라인이 나와야 한다.
- 스크롤: 하단 근접 시에만 자동 스크롤. 사용자가 위로 올려 둔 상태면 스크롤을 뺏지 않고 "새 메시지" 배지 표시.
- 세션 상태는 sessionStorage에 직렬화해 새로고침에도 유지(탭 새로 열면 초기화).
- 대본 내용: 보험 상담 흐름(도입 → 가격 문의 반복 → 가설계표 제안 → 저항/분기). Figma의 운전자보험 대화를 기반으로 작성.

## Feature 3 — 대화 온도 분석 (핵심)

### 표시 지표

Figma는 "이탈 확률"을 대표 지표로 노출한다. 내부 분석은 4축으로 하고, 표시 지표는 그로부터 산출한다.

- **이탈 위험도(%)** = 100 − 온도. 큰 숫자 + 단계 뱃지로 표시.
- 4단계 밴드(Figma 범례 그대로): 안전 0–29 / 주의 30–49 / 위험 50–69 / 긴급 70+.
- 4분할 세그먼트 게이지: 현재 밴드까지 채색, 각 세그먼트 아래 단계명·범위 범례.

### 분석 파이프라인

1. **LLM은 축별 평가만 담당** (최종 숫자를 직접 뽑지 않는다):
   - engagement(관심·참여), trust(신뢰), intent(가입 의향), resistance(저항) — 각 0~100 점수 + 근거 발화 인용 + 한 줄 노트.
   - 추가 필드: confidence(low/medium/high), change(rising/flat/falling), trigger(변화를 만든 발화), nextAction(상담사 제안).
2. **최종 온도는 코드에서 가중합** (초기 가중치: intent 0.40, engagement 0.25, trust 0.20, resistance 0.15 역방향). 가중치는 상수로 분리해 프롬프트 수정 없이 튜닝 가능해야 한다.
3. **인용 환각 가드**: LLM이 반환한 인용은 실제 메시지 배열에서 검증(공백 정규화 후 포함 검사). 검증 실패 인용은 폐기하고, 축의 인용이 전부 탈락하면 해당 축 confidence를 강등. 통과한 인용은 원본 메시지 ID와 함께 저장한다.
4. **스냅샷 이력**: 매 분석 결과를 스냅샷 배열로 축적. 다음 분석 호출 시 직전 스냅샷을 앵커로 제공해 상대 평가(delta)를 유도한다.
5. **초반 가드**: 고객 발화가 3개 미만이거나 confidence가 low면 숫자·게이지를 숨기고 "판단 근거 부족" 상태로 표시.

### API 설계

- `POST /api/temperature` — 요청: 메시지 배열 + 직전 스냅샷(선택). 응답: Zod 스키마로 검증된 분석 결과.
- 모델: `claude-opus-5`, structured output(스키마 강제), effort low.
- system 프롬프트에 평가 루브릭 + 앵커 예시(cold/neutral/hot 실대화 조각과 정답 점수)를 고정으로 두고 prompt caching 적용. system에 타임스탬프 등 가변 값 금지.
- 클라이언트는 React Query mutation으로 호출. 분석 중 패널에 로딩 상태, 실패 시 직전 스냅샷 유지 + 재시도 버튼.

### 호출 시점

- 기본: 고객 발화가 도착할 때마다 자동 분석 (Figma의 "실시간 분석" 표시와 일치).
- 연속 발화 시 직전 요청이 진행 중이면 최신 상태로 1건만 대기(중복 호출 방지).
- 수동 "다시 분석" 트리거도 제공.

## Feature 4 — AI 상담 코치 패널 UI (Figma 기준)

위에서 아래로:

1. **패널 헤더**: AI 마크 + "대화 온도계" 제목, 우측 "실시간 분석" 상태 점.
2. **이탈 온도계 카드**: "현재 이탈 확률" 라벨, 큰 % 수치(밴드 색상), 단계 뱃지(예: 긴급), 4분할 게이지, 단계 범례.
3. **턴별 추이 카드**: "턴별 이탈 확률" 제목, 직전 대비 변화(+23% ↑ 형식), 스냅샷 기반 라인 차트(기준선 + 현재 값 강조점), X축 턴 라벨(1턴~N턴).
4. **AI 코칭 알림 카드**: 경고 배경, 분석의 nextAction 기반 코칭 메시지(예: "3턴 연속 가격만 묻습니다…"), 추천 실행 버튼(예: "가설계표 보내기"). 버튼 클릭 시 프로토타입에서는 해당 문구를 입력창에 채우거나 빠른 작업을 실행하는 정도로 연결.
5. **분석 근거 푸터**: 판단 근거 요약 한 줄(예: "가격 질문 반복 · 정보입력 거부 신호 · 최근 3개 턴 기준"). 근거 인용 클릭 시 대화 목록의 해당 메시지로 스크롤 + 하이라이트.

밴드 색상은 Figma 팔레트를 따른다: 안전(녹색), 주의(황색), 위험(연적색), 긴급(적색).

## Data Model (개념)

- **Customer**: id, 이름, 연령대, 관심 상품, 유입 경로, 태그, 최근 메시지, 상태.
- **Message**: id, role(counselor/customer), text, 세션 오프셋 시각.
- **ScriptStep**: 기대 상담사 발화(힌트용), 고객 응답 또는 분기 후보 목록.
- **AxisReading**: score, quotes(검증 후 messageId 연결), note.
- **TemperatureSnapshot**: 4축 AxisReading, 산출된 온도·이탈 위험도·밴드, confidence, change, trigger, nextAction, 대상 턴 번호.

## Non-Goals

- 실시간 통신(WebSocket/SSE), 인증, 영속 DB, 실제 고객 응대 연동.
- 고객 측 AI 응답 생성(대본 재생으로 충분; 필요 시 후속 확장).
- 상태 탭/검색의 실제 동작, 고객 목록의 CRUD.
- 모바일 반응형(1440 데스크톱 기준; 최소한의 축소 허용만).

## Acceptance Criteria

1. 워크스페이스가 Figma 시안과 유사한 4컬럼 레이아웃으로 렌더링된다.
2. 상담사가 메시지를 보내면 타이핑 인디케이터 후 대본의 고객 응답이 나타난다.
3. 고객 발화 도착 시 온도 분석이 자동 실행되고, 이탈 확률·밴드·게이지가 갱신된다.
4. 턴별 추이 차트가 스냅샷 누적에 따라 그려지고 직전 대비 변화량이 표시된다.
5. AI 코칭 알림이 분석 결과의 nextAction으로 갱신된다.
6. 분석 근거 인용을 클릭하면 대화의 해당 메시지로 스크롤·하이라이트된다.
7. 검증 실패(환각) 인용은 UI에 노출되지 않는다.
8. 고객 발화 3개 미만 시 "판단 근거 부족" 상태가 표시된다.
9. 분기 스텝에서 다른 고객 응답을 선택하면 온도 추이가 그에 맞게 달라진다.
10. API 키는 서버 환경변수로만 사용되며 클라이언트 번들에 노출되지 않는다.
11. 새로고침 후에도 진행 중이던 세션(메시지·스냅샷)이 유지된다.

## Open Questions

1. 4축 정의와 가중치가 보험 상담 현장 기준과 맞는지 — 업권 특화 신호(가족 상황 공개, 기존 보험 언급 등)를 축이나 프롬프트에 반영할지. 초기값으로 진행하되 튜닝 가능하게 둔다.
2. 실제 상담 스크립트/녹취 샘플 제공 여부 — 있으면 mock 대본과 앵커 예시를 교체한다.
3. 코칭 알림의 "추천 실행" 버튼이 프로토타입에서 어디까지 동작해야 하는지(문구 삽입 vs 빠른 작업 실행).
