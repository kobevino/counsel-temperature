# 상담 워크스페이스 — 대화 온도계 프로토타입

보험 상담사가 채팅 상담 중 AI가 읽어낸 고객의 **대화 온도**를 실시간으로 확인하는 어드민 프로토타입.
온도는 높을수록 따뜻한(전환에 가까운) 상담이다 — 이전 버전의 "이탈 위험도"와 방향이 반대이므로 두 수치를 섞어 쓰지 말 것.

- 스펙: `_specs/counsel-temperature-workspace.md`
- 고객 목록은 mock 데이터. 고객 답변은 `POST /api/customer-reply`가 키워드 템플릿 룰 베이스로 생성하고, 온도 분석은 `POST /api/temperature`(OpenAI API)가 담당. 온도 분석은 API 키가 없으면 결정적 mock으로 폴백.

## 실행

```sh
pnpm install

# 1) API 키 없이 데모 (결정적 mock 분석)
TEMPERATURE_MOCK=1 pnpm dev

# 2) 실제 OpenAI 분석
cp .env.example .env.local   # OPENAI_API_KEY 입력
pnpm dev
```

http://localhost:3000 접속. `OPENAI_API_KEY`가 없으면 자동으로 mock 분석으로 동작한다.

## 온도 로직

```
온도 = 0.40·intent + 0.25·engagement + 0.20·trust + 0.15·(100 − resistance)
```

초기값 45/60/50/20 → **초기 온도 55**. 구간은 따뜻함 70+ / 미온 55–69 / 식는 중 40–54 / 차가움 25–39 / 이탈 임박 0–24.

점수는 LLM이 매기지 않는다. LLM은 **어떤 신호가 어느 발화에서 나왔는지만** 코드로 집어내고(`lib/signals.ts`의 증감표), 초기값에서 Δ를 누적하는 산술은 시스템이 한다. 무응답·응답 속도·발화 길이 같은 시간 신호는 타임스탬프에서 직접 계산한다(`lib/clock.ts`, 야간 22:00~08:00 제외). 덕분에 같은 대화는 항상 같은 온도가 나오고, mock 경로와 LLM 경로가 같은 산술을 공유한다.

개입 판단은 `lib/intervention.ts`:

- **T1** 온도 ≤ 39 · **T2** 한 턴 하락 ≥ 8 · **T3** 3턴 하락 합 ≥ 12 — 하나라도 걸리면 개입
- **B1** 직전 3턴 내 개입함 · **B2** 명시적 거절 이후(처방 불가, 정중 종료만) · **B3** 상담사가 이미 그 축의 처방대로 대응 중 · **B4** 2턴 연속 상승 · **B5** 하락의 과반이 상담사 귀책(개입 카드 대신 운영 알림)
- 가장 많이 나빠진 축이 처방을 정한다 — intent=대안 설계 / engagement=요약 + 종료 예고 / trust=개략 금액 먼저 / resistance=낮춘 안 제시

## 데모 방법

1. 고객을 고르고 입력창에 실린 대본을 그대로 보내면 대화가 한 턴씩 재생된다. 대본을 벗어나 자유롭게 입력하면 페르소나 응답 엔진이 이어받는다.
2. 고객 발화마다 우측 온도가 자동 갱신된다. 고객이 조용해도 10분을 넘기면(야간 제외) 상담사 발화 때마다 다시 읽어 engagement 하락을 반영한다.
3. 개입 카드는 T1·T2·T3 중 하나라도 걸리고 B1~B5에 막히지 않을 때만 뜬다. 카드 헤더에 어떤 트리거가 걸렸는지, 주도 축이 무엇인지 함께 표시된다.
4. 하단 근거 인용 칩을 클릭하면 해당 발화로 스크롤·하이라이트된다.

권장 시연 순서는 A(정미경) → B(한영숙) → C(박준호) → E(오성철). 무응답 케이스는 D(최수민).

## 구조

- `app/api/customer-reply/route.ts` — 고객 답변 생성. `lib/mock/replies.ts`의 키워드 템플릿 룰 베이스로 동작하며 외부 API를 호출하지 않는다.
- `app/api/temperature/route.ts` — 온도 분석. LLM은 신호 코드 + 근거 발화만 뱉고, 인용은 `lib/quotes.ts`에서 실제 발화와 대조해 검증한다(환각 가드 — 검증에 실패한 신호는 점수에 들어가지 못한다).
- `lib/signals.ts` — 신호별 축 증감표와 누적 계산기. `lib/prompt.ts`의 신호 목록은 이 표에서 생성되므로 둘이 어긋날 수 없다.
- `lib/clock.ts` — 타임스탬프에서 계산하는 신호(무응답 단계·응답 속도·발화 길이 감소).
- `lib/intervention.ts` — T1~T3 트리거, B1~B5 차단, 주도 축 판정, 축별 처방.
- `store/session.ts` — zustand(비영속). 상담사 발화 → 대본 재생/고객 답변 요청, 스냅샷 이력. 새로고침하면 모든 대화가 초기 상태로 리셋된다.
- `hooks/useTemperature.ts` — react-query mutation, 고객 발화·장기 무응답마다 자동 트리거(latest-wins 중복 방지).
- `lib/mock/` — 고객 5명 + 시연 대본 + 키워드 응답 템플릿 + 결정적 신호 감지기(`detect.ts`).
- `components/coach/` — 온도 게이지, 턴별 온도 추이, 개입 카드, 분석 근거.

가중치·구간은 `lib/score.ts`, 신호 증감값은 `lib/signals.ts`, 개입 기준값은 `lib/intervention.ts` 상단 상수에서 튜닝한다.
